# sparse-activation-kwta

**稀疏激活判定（免乘法器动态阈值 vs. k-WTA）的定点参考模型、可综合 RTL 与硬件代价对比**

> 16-bit 定点 · 无乘法器 · 流式无缓存 · Python 整数位精确建模 + iverilog 联仿逐位对齐

关键词：`sparse activation` · `k-WTA` · `dynamic threshold` · `MAD / EMA` · `fixed-point` · `RTL` · `Verilog` · `SNN` · `neuromorphic` · `FPGA`

---

## 1. 解决什么问题

神经网络 / SNN 推理时，每个神经元都要回答一个问题：**这个样本该不该激活**。工程上常见两类判据：

| 机制 | 做法 | 代价 |
| --- | --- | --- |
| **k-WTA** | 二分搜索出第 K 大的阈值，把不小于它的神经元激活 | 必须缓存全部 N 个值；`BW` 轮串行比较 |
| **动态阈值** | θ = μ + β·MAD，用两个泄漏累加器在线估计分布，逐样本比较 | 2 个累加器、无缓存、无乘法器、单拍出结果 |

难点在于：两者在 RTL 里都是**定点运算 + 算术移位 + 截断**，浮点模型验证不了；很多开发环境里又没有 iverilog。所以本仓库做了四件事：

1. **位精确参考模型** —— [sparse_activate_sim.py](sparse_activate_sim.py)：用 Python 整数复现 Verilog 语义（有符号比较、`>>>` 地板取整、无回绕），可当 golden model；
2. **可综合 RTL** —— [sparse_activate.v](sparse_activate.v)：`dyn_thr_activate` / `kwta_activate`；
3. **联仿脚本** —— [verify_rtl.py](verify_rtl.py)：iverilog 跑 RTL，与模型**逐位**比对（位图 + 逐样本激活位）；
4. **硬件代价模型** —— [hw_cost.py](hw_cost.py)：归一化面积 / 关键路径 / 是否需缓存。

联仿过程中在 RTL 里查出 5 个功能问题（含一个恒定多激活 1 个的判据错误），见 §6。

## 2. 两条机制

### A. 动态阈值 `dyn_thr_activate`

```
μ   = mean_acc >>> 6              # 累加器里存的是 μ·2^6（Q6），右移还原
MAD = mad_acc  >>> 6
θ   = μ + ((MAD * 33) >>> 4)      # β = 33/16 = 2.0625，纯移位加
act = (s >= θ)

# 泄漏积分 / 一阶 IIR，时间常数 τ = 2^6 = 64 个样本
mean_acc += s        - (mean_acc >>> 6)
mad_acc  += |s - μ|  - (mad_acc  >>> 6)
```

- **免乘法器**：33 = 32 + 1 → `(MAD<<5 + MAD) >>> 4`；`|s-μ|` 用二补数取反 + 加法器。整条数据通路只有加/减/比较/移位。
- **流式**：只保留 2 个 32-bit 累加器，不缓存任何神经元值；每个样本只做一次比较，结果打一拍输出。
- **自适应**：阈值跟着输入的离散度走，输入幅度变化时激活率不会跟着漂。

### B. k-WTA `kwta_activate`

```
缓存 N 个 16-bit 值 → BW 轮二分搜索阈值 → 每轮 N 个比较器 + 归约计数 → 输出 N 位激活位图
```

判据是 **θ = max{ x : #{s ≥ x} ≥ K }**，即**第 K 大的值**：

- 数据**无并列**时，恰好激活 K 个；
- 阈值上有**并列**时，整组并列一起激活（至少 K 个，不会少），多出的个数 = 该阈值上的重复数；
- 16 轮把 `[−32768, 32767]` 的 2^16 个整数档位二分到底，与 16-bit 数据范围严格对应（`BW = DW`）。

> 判据必须是 `ge >= K` 而不是 `ge > K`：后者会收敛到 θ−1，**恒定多激活 1 个**（实测 K=4 时激活 5 个）。详见 §6。

## 3. Q 格式与参数怎么定的

| 参数 | 取值 | 定法 / 理由 |
| --- | --- | --- |
| `DW` | 16 | 输入位宽，与上游神经元的定点输出一致，signed，范围 ±32767 |
| `AW` | 32 | 累加器位宽。存 μ·2^6 和 MAD·2^6，即 **Q25.6**（1 符号 + 25 整数 + 6 小数） |
| `SHIFT` | 6 | EMA 时间常数 τ = 2^6 = 64 个样本 |
| `BNUM`/`BSH` | 33 / 4 | β = 33/16 = 2.0625，即 2 + 1/16 |
| `N` / `K` | 2000 / 100 | K/N = 5%，与动态阈值的 5% 对齐才可比 |
| `BW` | 16 | 二分轮数 = 数据位宽；16 轮恰好把 2^16 个档位分到底 |
| `CW` | `clog2(N+1)` = 11 | 计数位宽，要数得下 0..N（N=2000 需 11 位） |

### 3.1 β 为什么是 2.0625（这决定激活率是不是 5%）

正态分布下平均绝对偏差与标准差的关系是解析的：

```
E|X − μ| = σ·√(2/π) = 0.7979σ        （MAD 的定义）
```

希望阈值落在 **1.645σ**（单尾概率 5%，正好等于 K/N = 100/2000）：

```
β = 1.645 / 0.7979 = 2.0620  ≈  2.0625 = 33/16
θ ≈ μ + 2.0625·0.7979σ = 1.645σ   →   P(s ≥ θ) ≈ 5%
```

为什么是 `33/16` 而不是 `32/16`：`32/16 = 2.0` 会把 θ 压到 1.596σ，激活率变成约 5.5%，偏多；`33/16` 才命中 1.645σ。而 33 = 2^5 + 1，×33 = 左移 5 位再相加，**不需要乘法器**。

分母取 16 是因为 β 的步进 1/16 = 0.0625（约 3%），对 5% 的激活率已经够细，同时 `MAD × 33` 的位宽增长可控。

### 3.2 为什么累加器里要存 μ·2^SHIFT，而不是直接存 μ

小信号（σ ≈ 10）时 μ 只有个位数，如果先截成整数再积分，`s − μ` 的小数部分会被反复地板掉，累加器掉进死区、收敛不到真实均值。保留 6 位小数后，`|s−μ|` 的期望（≈7.98）才能稳定进入积分器 —— 这是整个设计能"无缓存流式"的前提。

### 3.3 位宽够不够（Python 无界整数 vs. 32 位寄存器）

| 量 | 上界 | 说明 |
| --- | --- | --- |
| `mean_acc` | ≤ 32767·64 ≈ 2^21 | 稳态即 μ·2^6 |
| `mad_acc` | ≤ 65535·64 ≈ 2^22 | 稳态即 MAD·2^6 |
| 实测峰值 | 6103 | 随机数据；测试里另有 ±32767 边界值用例 |

与 2^31 相比有几百倍余量，**不存在回绕**，所以 Python 的大整数运算与 32-bit 寄存器的结果逐位相同 —— 这是"能用 Python 验证 RTL"的关键前提。模型里对此有硬断言：一旦 `|acc| ≥ 2^31` 直接抛 `OverflowError`（对应测试 `test_accumulator_stays_in_range`）。

### 3.4 阈值本身是整数

`θ = μ + (MAD*33)>>4` 全程整数运算，没有四舍五入，与 RTL 的截断行为完全一致（因此也带来 §6 末尾的小幅度偏差）。

## 4. 验证结果

环境：Python 3.12 + numpy 2.3 + Icarus Verilog 14；随机种子 0；数据先 `clip` 到 int16 再送模型。统计窗口统一丢掉前 1000 点（≈15τ，EMA 收敛期）。

### 4.1 动态阈值：激活率

| 输入分布 | 激活率（后 3000 点） |
| --- | --- |
| N(0, 10) 小离散度 | **7.20%** |
| N(0, 100) 大离散度 | **5.43%** |
| N(0,10) + N(0,100) 混合 | **6.07%** |
| 理论目标（1.645σ） | 5.00% |

**读法：**

- 输入幅度变化 10 倍，激活率只在 5.4%–7.2% 之间，**没有随幅度漂移** —— 这就是 μ + β·MAD 的自适应性质。
- σ = 100 时 5.43% 与理论 5% 基本吻合，残差来自 EMA 纹波 + 有限样本。
- σ = 10 时偏到 7.2%，**不是算法错，是定点 + 估计噪声**：MAD 在乘 β 之前先被 `>>>6` 截成整数（7.98 → 7 或 8，1 LSB 就是 12.5% 的相对误差），再叠加 τ = 64 的 EMA 纹波，阈值在 10–19 之间抖动、均值 15.2，低于理想的 16.45。若直接用未截断的 16.45 判阈，激活率是 4.6%。修法见 §6 末尾。

### 4.2 k-WTA：是不是恰好 K 个

| 指标 | 结果 |
| --- | --- |
| N / K | 2000 / 100 |
| 收敛阈值 `mid` | **157** |
| 实际激活数 | **100**（误差 0） |
| 严格 `> 157` 的个数 | 97 |
| 恰好 `== 157` 的个数 | 3 |

阈值取到「第 100 大的值」157，激活数正好 100。若改回旧判据 `ge > K`，阈值会停在 156（= θ−1），激活 102 个：多出的 2 个正是值等于 156 的并列样本。

### 4.3 幅度不变性对比

| 输入 | k-WTA 激活率 | 动态阈值激活率 |
| --- | --- | --- |
| 低幅度 σ = 10 | 5.65% | 7.60% |
| 高幅度 σ = 100 | 5.05% | 5.30% |

k-WTA 目标恒为 K/N（5%），低幅度下偏到 5.65% 是整数并列所致（113 个里有 13 个是阈值上的并列）；动态阈值同样是分布自适应，小幅度下受量化影响偏大。

### 4.4 一致性：RTL ↔ 模型 逐位联仿

`verify_rtl.py` 生成向量 → 编译 RTL → 跑仿真 → 把 k-WTA 位图与动态阈值逐样本激活位和模型比对：

| 配置 | k-WTA 位图 | 动态阈值流 |
| --- | --- | --- |
| N=64, K=4, 4 帧 | 4/4 帧一致，激活数 [4, 4, 4, 4] | 2000/2000 样本一致 |
| N=200, K=20, 4 帧 | 4/4 帧一致，激活数 [20, 37, 20, 20]† | 3000/3000 样本一致 |
| N=2000, K=100, 2 帧 | 2/2 帧一致，激活数 [100, 135]† | 800/800 样本一致 |

† 该帧是**并列值压力用例**（取值 0..15），阈值上有大量重复，激活数按定义 ≥ K。

对齐的关键点：

| Verilog | Python 模型 | 说明 |
| --- | --- | --- |
| `mean_acc >>> SHIFT` | `mean_acc >> SHIFT` | 负数右移 = 算术右移 + 向负无穷取整，两者一致 |
| `signed [DW-1:0]` + 符号扩展 | 直接 `int` | 16-bit 有符号映射为 Python 整数 |
| `s_ext >= thr` | `s >= thr` | 有符号比较 |
| 32-bit 寄存器回绕 | 无界整数 | 峰值 6103 ≪ 2^31，等价；越界会抛异常 |
| k-WTA 状态机（16 拍串行） | 16 轮循环 | 每轮 1 次 N 路计数，最后用第 16 轮的 `mid` 输出位图 |

**验证边界**：这是**功能级**联仿（Icarus Verilog 14，行为仿真），不做综合、不评估时序/面积；面积数字来自 §5 的估算模型。

## 5. 硬件代价（归一化到 16-bit 加法器）

`python hw_cost.py`，N = 2000，K = 100：

| 实现 | 面积（归一） | 相对 k-WTA | 关键路径 | 需缓存 N 个值 |
| --- | --- | --- | --- | --- |
| k-WTA（二分搜索选阈值） | 64,544 | 1.00× | 192 | 是（2000 个寄存器） |
| 动态阈值 μ+βσ（含开方） | 55,844 | 0.87× | 16 | 否（2 个累加器） |
| **动态阈值（平均绝对偏差）** | **8,400** | **0.13×** | **15** | 否（2 个累加器） |

结论：动态阈值真正省的地方是**免乘法器 + 流式无缓存**（约 7.7 倍），而不是"不用排序" —— 如果老老实实算 σ（2000 个乘法器 + 1 个开方），面积只省 13%，优势基本被乘法器吃光。

> 这是设计前期的估算模型（算子数 × 归一化单价），不是综合结果；真实面积 / 功耗仍需 Vivado / Quartus。

## 6. 修复记录（联仿中查出的问题）

装上 iverilog 后，原来的 RTL 跑出来的 k-WTA 只有 3 个激活（K=4），于是逐拍 dump 状态机，查出 5 个功能问题。下表全部已修复，并由 `verify_rtl.py` 的逐位比对守住。

| # | 位置 | 问题 | 后果 | 修法 |
| --- | --- | --- | --- | --- |
| 1 | `kwta_activate` | `act` 既在组合 `always` 里赋值，又在复位分支里赋值（**多驱动**） | 综合工具报错或行为不确定 | `act` 改成 `wire`，用 `generate` 单一驱动 |
| 2 | `kwta_activate` | `mid <= (lo + hi) >>> 1` 是非阻塞赋值，读到的是**更新前**的 lo/hi | `mid` 滞后一拍，16 轮里只有 15 轮有效 | 先组合算出 `lo_nxt/hi_nxt`，再用它们求中点 |
| 3 | `kwta_activate` | `(lo + hi)` 在 16 位下溢出（范围要到 ±65536） | 中点回绕成负数 | 用 `DW+1` 位求中间和 |
| 4 | `kwta_activate` | 初值 `{VMIN[DW-1], VMAX[DW-1:1]}` 实际是 **−16385**，不是 −1 | 二分起点偏离，少一轮 | 直接写 −1 |
| 5 | `kwta_activate` | 判据用 `ge > K`，收敛到 `#{s≥x} > K` 的一侧 | **恒定多激活 1 个**（K=4 → 5） | 改 `ge >= K`，收敛到第 K 大的值 |
| 6 | 测试台 | 在 `posedge` 后用阻塞赋值改激励（竞态）；`%b` 按 MSB-first 输出 | 结果不可复现 / 位序与模型相反 | 改 `negedge` 驱动；按索引逐位输出 |
| 7 | 参考模型 | numpy 标量（int16）直接参与加减会按 int16 回绕 | 与 32 位寄存器不再等价 | 循环内强制 `int()`，并加回归测试 |

**保留的设计取舍（未改）**：MAD 先 `>>>6` 截成整数再乘 β，σ = 10 时相对误差可达 12.5%，激活率从 5% 偏到 7.2%。两种可选改法（会改变数值结果，故默认未启用）：

- 不先截断：`θ = μ + ((mad_acc * 33) >>> (SHIFT + 4))`，把小数位一路带进乘法（RTL 只改一行）；
- 或在移位前做四舍五入（round-half-up），代价是加一个常数。

**其它小修**：数据标签与生成数据不符（脚本曾打印 `N(0,400)`，实际是 `N(0,10)+N(0,100)` 混合）；C 段统计窗口与 A 段不一致（500 vs 1000）；`hw_cost.py` 里重复定义的 `LOG2N` 死代码、以及结论里"1/4 量级"与实测 0.13× 不符。

## 7. 快速开始

```bash
# 依赖：Python 3.8+、numpy；iverilog 可选（Windows 可从 bleyer.org 下载安装包）
python sparse_activate_sim.py            # 激活率 / k-WTA / 幅度不变性三组检查
python sparse_activate_sim.py --json     # 机器可读结果
python sparse_activate_sim.py --check    # 只做断言，CI 用（失败退出码非 0）
python hw_cost.py                        # 硬件代价对比表
python -m unittest -v test_golden        # 纯 Python 回归测试（不需要 iverilog）
python verify_rtl.py                     # RTL ↔ 模型 逐位联仿（需要 iverilog）
```

`verify_rtl.py` 的常用参数：

```bash
python verify_rtl.py --n 2000 --k 100 --frames 2 --samples 800   # 全规模
python verify_rtl.py --keep                                      # 保留 build/cosim 波形与中间文件
```

没有 iverilog 时 `verify_rtl.py` 会打印 `SKIP` 并返回 0；CI 里加 `--require-tools` 可以强制失败。

想直接跑 RTL 也行（没有向量文件时测试台用内置随机数据做冒烟检查）：

```bash
iverilog -g2012 -o sim tb_sparse_activate.v sparse_activate.v && vvp sim
# 参数: -P tb_sparse_activate.N=2000 -P tb_sparse_activate.K=100
```
